课题6：以太网帧结构

核心术语

以太网
目前最主流的局域网技术标准，由IEEE 802.3定义。它规定了物理层和数据链路层的MAC子层标准。
帧
数据链路层的协议数据单元（PDU），是网络中传输的基本数据块，包含目的地址、源地址、数据和校验信息。
前导码
帧开头的7个字节（10101010...），用于让接收方的时钟与发送方同步，就像跑步比赛前的倒计时。
帧起始定界符
紧跟前导码的1字节（10101011），最后两位为11，告诉接收方：同步完成，帧的实际内容从下一个字节开始。
MAC地址
网络接口卡（NIC）的唯一硬件标识，长度为48位（6字节），通常写成如 AA:BB:CC:DD:EE:FF 的格式。
类型字段
以太网帧中标识上层协议类型的字段，如0x0800表示IPv4，0x0806表示ARP，0x86DD表示IPv6。
FCS
帧校验序列，位于帧尾部的4字节CRC校验码，用于检测帧在传输过程中是否发生了比特错误。
MTU
最大传输单元，以太网的MTU为1500字节，表示帧中数据部分的最大长度。超过MTU的数据需要分片传输。

为什么要学帧结构？

上一课我们知道了物理层负责传输比特流，但比特流只是一堆0和1，接收方怎么知道一个完整的数据块从哪里开始、到哪里结束？怎么知道这个数据是发给谁的？怎么判断数据有没有在传输中出错？

这些问题都需要数据链路层来解决。数据链路层把上层传下来的数据封装成帧（Frame），就像把一封信装进信封——信封上写着收件人地址、寄件人地址，信封里是信的内容，封口处还有防拆标记。以太网帧就是这个"信封"。

以太网的历史：从2.94Mbps到100Gbps

以太网（Ethernet）诞生于1973年，由施乐公司的Robert Metcalfe发明。最初的以太网只有2.94Mbps的速率，使用同轴电缆。后来IEEE以以太网为基础制定了IEEE 802.3标准，经过几十年的演进，速率从10Mbps、100Mbps、1Gbps一路发展到今天的10Gbps、40Gbps、100Gbps甚至更高。

现在全世界的局域网几乎都是以太网，可以说它是局域网技术的事实标准。

Ethernet II帧格式

目前最常用的以太网帧格式是Ethernet II（也叫DIX帧），由DEC、Intel和Xerox三家公司联合制定。一个完整的Ethernet II帧由以下部分组成：

帧的结构

字段 长度 说明
前导码（Preamble） 7字节 交替的1和10101010...，用于时钟同步
帧起始定界符（SFD） 1字节 10101011，标记帧内容即将开始
目的MAC地址 6字节 接收方的网卡地址
源MAC地址 6字节 发送方的网卡地址
类型（EtherType） 2字节 上层协议类型标识
数据（Payload） 46-1500字节 实际要传输的数据
FCS 4字节 CRC校验码

逐字段详解

前导码 + SFD（共8字节）

这是帧的"热身"阶段。接收方的网卡需要和发送方保持时钟同步才能正确读取比特流，就像两个合唱团需要先对准节拍一样。前导码的7个字节都是交替的10101010，这种规律性的信号让接收方的时钟能够锁定发送方的节奏。

SFD的最后一个字节是10101011，注意最后两位是11而不是10，这个微妙的变化告诉接收方：同步结束，后面就是真正的帧内容了。

目的MAC地址和源MAC地址（各6字节）

这是帧的"收件人"和"寄件人"。MAC地址是48位（6字节）的硬件地址，通常写成如 00:1A:2B:3C:4D:5E 的格式。

有一个细节：MAC地址的第一个字节的最低位用来区分单播和多播：

  • 最低位为0 → 单播（发给一个特定设备）
  • 最低位为1 → 多播（发给一组设备）

另外，如果目的MAC地址是 FF:FF:FF:FF:FF:FF，这就是广播地址，表示发给局域网内的所有设备。

类型字段/EtherType（2字节）

这个字段告诉接收方：帧里面的数据应该交给哪个上层协议处理。常见的类型值：

类型值 协议
0x0800 IPv4
0x0806 ARP
0x86DD IPv6

你可以把这个字段想象成快递包裹上写的"内附：文件/食品/电子产品"，让收件人知道该怎么处理。

数据字段（46-1500字节）

这是帧的"正文"，存放上层协议传下来的数据。以太网规定：

  • 最小长度：46字节（不够要填充）
  • 最大长度：1500字节（这就是MTU）

为什么要设最小长度？这和**冲突检测（CSMA/CD）**机制有关——帧必须足够长，才能在发送完毕之前检测到是否发生了冲突。虽然现代交换式以太网已经很少使用CSMA/CD，但这个限制保留了下来。

如果上层数据超过1500字节怎么办？那就需要在上层进行分片，把大数据块拆成多个帧来传输。

FCS——帧校验序列（4字节）

FCS使用CRC-32算法，发送方对帧的内容（从目的MAC到数据字段）计算一个32位的校验码，放在帧尾。接收方收到帧后用同样的算法再算一遍，如果结果和FCS不一致，说明帧在传输过程中出了错，接收方会直接丢弃这个帧。

IEEE 802.3帧格式

除了Ethernet II，还有IEEE 802.3定义的帧格式。两者的主要区别在于：Ethernet II用2字节的类型字段标识上层协议，而802.3用2字节的长度字段标识数据部分的长度。

在实际应用中，Ethernet II帧更为常见。现在的以太网设备通常两种格式都支持，而且通过字段值的范围可以自动区分：类型字段值大于等于1536（0x0600）就是Ethernet II，小于1536就是802.3。

帧的传输过程

当一台电脑要发送数据时，整个过程是这样的：

  1. 封装：数据链路层从网络层拿到数据包，加上MAC头部（目的MAC、源MAC、类型）和FCS尾部，封装成帧
  2. 发送：物理层把帧转换成比特流，通过线缆发送出去
  3. 接收：接收方的物理层收到比特流，还原成帧
  4. 校验：数据链路层检查FCS，如果校验失败就丢弃
  5. 解封装：去掉MAC头部和尾部，把数据部分交给上层协议

本课小结

  • 以太网是目前最主流的局域网技术，由IEEE 802.3标准定义
  • 数据链路层将数据封装成帧进行传输，帧是数据链路层的PDU
  • Ethernet II帧由前导码、SFD、目的MAC、源MAC、类型、数据、FCS组成
  • 前导码和SFD用于时钟同步和帧起始标记
  • MAC地址是48位的硬件唯一标识
  • 类型字段标识上层协议（0x0800=IPv4，0x0806=ARP）
  • FCS使用CRC-32校验，检测传输错误
  • 以太网帧数据部分最小46字节，最大1500字节（MTU）

练习题

1. 以太网帧中，哪个字段用于标识上层协议类型？

答案：C

解析：类型字段（EtherType）占2字节，用于标识帧中数据应该交给哪个上层协议处理，如0x0800表示IPv4，0x0806表示ARP。

2. 以太网帧数据部分的最大长度为________字节，这个值称为MTU。

答案：1500

解析：以太网的MTU（最大传输单元）为1500字节，超过这个长度的数据需要在上层进行分片传输。

3. 以太网帧的FCS字段使用什么算法来检测传输错误？

答案：C

解析：FCS使用CRC-32算法计算校验码。发送方计算后附加在帧尾，接收方重新计算并比对，不一致则丢弃帧。

4. 以太网帧中前导码的作用是什么？

答案：B

解析：前导码是7个字节的交替10101010模式，用于让接收方的时钟与发送方同步，就像跑步比赛前的倒计时。

5. 以太网帧数据部分的最小长度是多少？为什么要有最小长度限制？

答案：最小长度为46字节。这是为了配合CSMA/CD冲突检测机制，确保帧足够长，使得发送方在发送完毕之前能检测到是否发生冲突。

解析：虽然现代交换式以太网已很少使用CSMA/CD，但最小帧长限制保留了下来，这也是以太网兼容性设计的体现。
